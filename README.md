# Spencer's Python Notebook

A separate portfolio for 32 Python files from CSE 110 Weeks 1–8. Start with [index.html](index.html).

[Visit the portfolio](https://spencersmith810.github.io/assignment-portfolio/) · [GitHub repository](https://github.com/spencersmith810/assignment-portfolio)

## Open it

Open `index.html` directly in a browser. The portfolio uses ordinary HTML, CSS, and JavaScript; it needs no package installation, build service, database, or account. For consistent theme and checklist storage across pages, use the local server below; browsers handle storage for directly opened files differently.

For a local web server, run this from the original `cse110` folder:

```sh
python3 -m http.server 8000 --directory assignment-portfolio
```

Then visit <http://localhost:8000>. Stop the server with Ctrl+C.

This folder is a dedicated Git repository. GitHub Pages serves the committed files from the root of its `main` branch; the original coursework and its root homepage remain separate. A `.nojekyll` file tells Pages to serve the generated site directly.

If you clone this repository on its own, run `python3 -m http.server 8000` from the cloned folder and visit <http://localhost:8000>. You can verify the published snapshot with `python3 -B check.py` without the original coursework folders.

## What is included

- One searchable collection, eight week overviews, and 32 individual project pages.
- Descriptive names, plain-language explanations, skill tags, and step-by-step walkthroughs.
- Real sample output generated by running each original Python program with documented example inputs.
- Expandable Python source, syntax colors, line numbers, a copy button, and individual downloads.
- Browser versions of the games and exercises, plus clearly labeled teaching explorations for lesson notes.
- A copy of the existing illustrated Week 6 Eevee game, with navigation back to the notebook.
- Light/dark themes, a browser-local reading checklist, mobile layouts, keyboard focus styles, reduced-motion support, and print styles.
- A ZIP containing all 32 cataloged original Python files.

`week4/teach2.py` contains only `import math`, so it has an explanation and original source but no invented finished program.

## How the files fit together

```text
assignment-portfolio/
├── index.html                  # Collection homepage (generated)
├── weeks/                      # Eight week pages (generated)
├── projects/                   # 32 project pages (generated)
├── assets/
│   ├── styles.css              # Shared layout, colors, responsive rules
│   ├── app.js                  # Search, theme, checklist, copy button
│   ├── demos.js                # Interactive browser adaptations
│   └── favicon.svg
├── source/week1/ ... week7/     # Byte-for-byte copies of Python files
├── games/rescue-eevee/          # A copy of the existing browser game
├── downloads/                  # Original-source ZIP
├── catalog.json                # Descriptions and example inputs
├── build.py                    # Generates pages and records real samples
├── check.py                    # Checks links, sources, and archive
└── source-manifest.json         # SHA-256 checksums for original sources
```

This is a small static-site generator: `catalog.json` contains the content, `build.py` makes the pages, and shared CSS/JavaScript supplies presentation and interaction. That separation prevents the same explanation or layout from needing to be maintained in 32 places. Generated pages remain readable even when JavaScript is disabled; only interactive features need it.

## Make an update

To change a title, description, walkthrough, or example input, edit `catalog.json`. To change appearance, edit `assets/styles.css`. To change a browser adaptation, edit `assets/demos.js`.

To refresh the generated pages after editing the catalog or an original Python assignment, run:

```sh
python3 -B assignment-portfolio/build.py
python3 -B assignment-portfolio/check.py
```

Run these from the original `cse110` folder. Rebuilding requires the sibling `week1`–`week7` folders and the original `week6/browser-game/dist` directory. It reads those originals and writes only inside `assignment-portfolio/`. It refreshes generated HTML, source copies, the copied game, the manifest, and the ZIP. Do not hand-edit generated pages if you want changes to survive a rebuild.

The already generated site can be copied or hosted on its own without Python. Rebuild only when you want a fresh snapshot of the coursework.

## Browser demos and original behavior

The browser does not run the original Python files. `demos.js` implements their central ideas in JavaScript, using forms, visible results, and game controls. The Python code and recorded sample run are the reference for exact console wording and formatting.

The lesson explorations intentionally add controls to fixed examples or unfinished placeholders and are labeled accordingly. The first Eevee demo reflects Week 5's inventory and branches; the copied illustrated game reflects the expanded Week 6 version. The word game keeps the original secret, repeated-letter membership behavior, and counting of wrong-length attempts.

Inputs in the portfolio demos are handled in the browser. Strings are escaped before insertion into generated HTML. The notebook has no analytics or server submission. Theme/checklist preferences use localStorage, with an in-memory fallback when storage is unavailable. The copied Eevee game inherits optional Google Fonts from its original stylesheet and uses local font fallbacks offline.

## Verify it yourself

The automated checker verifies local links and anchors, the completeness of the pages, exact Python snapshots, and archive contents. It does not replace checking browser interactions.

Useful manual checks:

1. Search for `guess`; only the word guessing project should remain.
2. Filter to Week 4; the five original Python files should appear.
3. In the word game, submit `cat`, then `planet`, then `mosiah`. It should count all three guesses, show the first wrong-length message, and finish on the last answer.
4. In the meal calculator, use the example inputs: subtotal $38.00, tax $2.28, total $40.28, and change $9.72. Adding a $5 tip makes the total $45.28.
5. Try `-3`, then `0` in the loop exercise. The negative is rejected and zero moves to the candy question. Only `yes` finishes that loop.
6. Explore a Week 5 rescue, then open the illustrated Week 6 version and try its extra choices.
7. Open the Python code, copy it, and download it. Compare it with the original file.
8. Mark a project as explored and navigate back. Confirm the checklist indicator and theme persist where browser storage is available.
9. Use Tab to navigate and resize the page to a narrow phone width.

The main lesson: a portfolio needs a presentation layer that explains a program, an interaction layer that makes its ideas tangible, and preserved source that lets a visitor verify the work.
